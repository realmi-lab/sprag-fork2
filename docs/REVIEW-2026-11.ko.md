# sprag 적대적 리뷰와 실측 (2026-11)

[rootstudioyaml/sprag](https://github.com/rootstudioyaml/sprag)를 두 가지 방법으로 검토했습니다.
- **코드 리뷰:** v3.108.0(`593c36d`)을 읽고 README의 주장과 실제 구현을 대조했습니다. 이후 나온 v3.109.0(`381613e`)의 변경도 확인했습니다.
- **실측:** 실험 두 가지를 직접 돌려 비용을 쟀습니다.

sprag 코드를 고친 수정본은 [`review-fixes-2026-11` 브랜치의 FORK_CHANGES.md](https://github.com/realmi-lab/sprag-fork2/blob/review-fixes-2026-11/FORK_CHANGES.md)에 있습니다. 이 저장소의 기본판은 그 뒤 sprag 코드를 걷어 내고 서브에이전트 하나(long-reader)로 줄였습니다. 아래 코드 링크는 원본 저장소의 v3.108.0을 가리킵니다.

## 요약

- **원리는 맞습니다.** 긴 Opus 세션에서 결과가 긴 읽기·탐색을 싼 모델에 넘기면 크게 아낍니다. 실측에서 파일 20개 읽기는 62~77% 아꼈습니다. 명령 한두 번으로 끝나는 짧은 조회는 본전에 가깝습니다.
- **sprag는 실제로 아낍니다.** 읽기가 많은 7턴 대화에서 sprag 3.108.0은 기본 Claude Code보다 19% 쌌고, 답의 정확도는 같았습니다.
- **하지만 장부가 부풀려져 있습니다.** 위임 4건 중 2건만 기록했는데 이미 $0.50이었습니다. 세션 전체의 실제 절감($0.39)보다 큽니다. 계산식을 실측 두 건에 대입하면 1.39배, 3.24배가 나옵니다.
- **모델에게 사실과 다른 말을 합니다.** 설치 때 묻지 않고 자동으로 등록한 룰을 "사용자가 이미 승인했다, 되묻지 말라"고 지시합니다.
- **보안 경계가 비대칭입니다.** 프리셋은 서명을 검증하는데, 같은 서버에서 오는 팀 룰은 서명 없이 전역 CLAUDE.md로 들어갑니다.
- **문서 변환 절감은 기준선이 과장돼 있습니다.** doc2md의 Office 문서 기준선은 어떤 독자도 쓸 수 없는 양(XML 전체)입니다.
- **매 호출에 비용이 붙습니다.** 설치하면 모든 메인 호출에 약 17,600토큰이 더 붙습니다(실측).
- **같은 효과는 더 가볍게 얻을 수 있습니다.** 읽기 전용 Haiku 서브에이전트 하나와 "긴 읽기는 그쪽으로"라는 지침 한 줄이면 됩니다.

## 1. 코드 리뷰에서 확인한 문제

### 1.1 절감 장부가 하위 에이전트가 헤맬수록 더 많이 아꼈다고 기록함

[`src/net-saving.js`](https://github.com/rootstudioyaml/sprag/blob/593c36d/src/net-saving.js#L117)의 v3 계산식은 "메인 모델이 직접 했다면 든 비용"을 이렇게 셉니다. 메인도 **하위 에이전트와 같은 횟수**로 호출했을 것이고, 그때마다 메인 컨텍스트 전체를 다시 읽었을 것이라고 가정합니다. 메인 컨텍스트가 30만 토큰이면 하위 호출 하나가 늘 때마다 그만큼의 다시 읽기 비용이 "절감"에 더해집니다. 하위 에이전트가 자기 작은 컨텍스트를 읽는 실제 비용보다 항상 큽니다.

같은 작업(새 입력 80k, 출력 5k)에서 하위 에이전트의 호출 수만 바꿔 계산했습니다. 메인은 Opus 5.5에 컨텍스트 30만 토큰, 하위는 Haiku 4.5입니다.

| 하위 호출 수 | 6 | 12 | 25 | 50 |
|---|---|---|---|---|
| v3가 기록하는 절감 | $1.11 | $1.47 | $2.27 | $3.79 |
| v4(이 포크) | $0.62 | $0.59 | $0.53 | $0.40 |

빠진 항목도 두 가지 있습니다.
- 하위 에이전트 첫 호출의 입력(자기 시스템 프롬프트·도구 정의)을 메인이 썼을 비용으로 셉니다. 실측에서 약 17,600토큰이었습니다.
- 위임을 지시하는 호출과 결과를 읽는 호출, 이 메인 호출 두 번의 다시 읽기 비용은 위임 쪽에 들어가지 않습니다.

그 밖에, 실패 판정은 도구 오류 밀도만 봅니다([`route-scan.js:383`](https://github.com/rootstudioyaml/sprag/blob/593c36d/src/route-scan.js#L383)). 그래서 오류 없이 틀린 답은 성공으로 셉니다. 돌아온 보고서의 토큰 수는 글자 수를 4로 나눠 추정합니다([`route-scan.js:451`](https://github.com/rootstudioyaml/sprag/blob/593c36d/src/route-scan.js#L451)). 한국어는 실제보다 적게 잡히지만, 금액 영향은 작습니다.

### 1.2 자동으로 등록한 룰을 "사용자가 이미 승인했다"고 모델에 알림

- [`seed-rules.js:18`](https://github.com/rootstudioyaml/sprag/blob/593c36d/src/seed-rules.js#L18)의 주석은 "사용자가 그 룰에 동의하지 않으면 아무것도 쓰지 않는다"고 적고 있습니다.
- 하지만 기본 설치는 대기 중인 프리셋을 모두 전역으로 등록합니다([`install.js:449`](https://github.com/rootstudioyaml/sprag/blob/593c36d/src/commands/install.js#L449)).
- 그런 다음 요청마다 붙는 힌트가 "사용자가 이미 승인한 위임 룰 … 되묻지 말고 위임하고"라고 지시합니다([`route-inject.js:573`](https://github.com/rootstudioyaml/sprag/blob/593c36d/src/route-inject.js#L573)).
- 룰 파일 머리말은 여기서 더 나아갑니다. 세션에 "요청 없이 하위 에이전트를 쓰지 말라"는 일반 지침이 있더라도, 여기 적힌 위임은 사용자가 요청한 것이라고 적습니다.
- [`route-inject.js`](https://github.com/rootstudioyaml/sprag/blob/593c36d/src/route-inject.js#L7) 첫 주석은 설계 의도를 밝힙니다. 산문으로 기본 지침과 다투면 조심스러운 쪽이 이기므로, 일치를 "이 요청에 대한 사실"로 진술해 모델이 따질 여지를 없앤다는 것입니다.

결과적으로 `npm i -g` 한 번이 모델에게는 "사용자의 명시적 승인"으로 전달됩니다.

### 1.3 팀 룰은 서명 없이 전역 CLAUDE.md가 불러오는 파일로 들어감

[`preset-sign.js`](https://github.com/rootstudioyaml/sprag/blob/593c36d/src/preset-sign.js#L7)는 서버가 털리거나 중간자가 있어도 래칫 문구나 에이전트 프롬프트를 모든 세션에 밀어 넣지 못하게 하려고 프리셋 묶음의 ECDSA 서명을 검증합니다. 그런데 팀 룰은 같은 백엔드에서 받은 텍스트를 줄바꿈만 접어 그대로 씁니다([`team-ratchet.js:154`](https://github.com/rootstudioyaml/sprag/blob/593c36d/src/team-ratchet.js#L154)). 이 파일은 전역 CLAUDE.md가 불러옵니다. 길이 제한도 없습니다.

문구에 `@~/.aws/credentials` 같은 토큰이 들어가면, Claude Code가 그 경로를 가져오기로 따라갈 수 있습니다. 서버나 팀 관리자 계정 하나가 털리면 모든 팀원 세션에 지시문이 들어가는 구조입니다.

### 1.4 doc2md의 Office 문서 기준선이 쓸 수 없는 양임

pptx·docx·xlsx의 절감 기준선은 본문 XML 전체를 4로 나눈 값입니다. 그래서 README의 발표자료 하나는 540,429토큰으로 잡힙니다. 이 양은 200k 창에 들어가지 않고, Read는 그 전에 잘립니다. 실제 대안은 python-pptx나 unzip으로 텍스트만 뽑는 것이고, 그 비용은 변환 결과와 비슷합니다.

같은 파일([`doc2md-ledger.cjs`](https://github.com/rootstudioyaml/sprag/blob/593c36d/src/doc2md-ledger.cjs))은 `.fig`에 대해서는 이 논리를 스스로 거부합니다. "쓸 수 없는 돈을 아꼈다고 하는 건 측정이 아니라 아첨"이라며 Read 상한(약 44,000토큰)을 기준선으로 씁니다. README의 "−95.9%"는 대부분 이 기준선에서 나옵니다.

### 1.5 OAuth 토큰을 기본으로 읽음

Enterprise 예산 게이지 하나를 위해, 기본 설정에서 Claude Code의 OAuth 액세스 토큰을 키체인에서 읽습니다([`oauth-budget.js:109`](https://github.com/rootstudioyaml/sprag/blob/593c36d/src/oauth-budget.js#L109)). 그리고 문서에 없는 `api.anthropic.com/api/oauth/usage`로 보냅니다.
- 보내는 곳은 Anthropic뿐이고, 토큰을 파일이나 로그에 남기지 않게 짠 것은 확인했습니다.
- 다만 요금제를 알아내려고 일단 읽는 구조라, 해당 없는 요금제에서도 하루 한 번은 읽힙니다.
- npm 패키지가 공급망 공격을 받으면, 계정 토큰을 읽는 경로가 이미 정상 기능으로 깔려 있는 셈입니다.

### 1.6 근거 자료의 문제

- **공개 벤치마크(59.1% 대 57.9%)**
  - 정규식이 프롬프트 모양으로 등급을 나눕니다. 수식이 있는지, 짧은 사실 질문인지, 4천 자가 넘는지를 봅니다. 이 기준은 사실상 데이터셋 구분과 같습니다.
  - 문서도 같은 데이터의 집계 통계로 기준을 다듬었다고 밝힙니다.
  - 홀수 번호만 떼어 낸 확인([`BENCHMARK.md:82`](https://github.com/rootstudioyaml/sprag/blob/593c36d/docs/BENCHMARK.md#L82))은 같은 데이터셋을 반으로 나눈 것이라, 데이터셋 단위 과적합을 거르지 못합니다.
  - 이득의 큰 몫은 SWE-Bench를 싼 모델로 보낸 데서 나옵니다([`BENCHMARK.md:77`](https://github.com/rootstudioyaml/sprag/blob/593c36d/docs/BENCHMARK.md#L77)). 그런데 제품은 수정·구현 요청을 위임하지 않습니다.
- **Proof(10건, 71회)**
  - 사례가 전부 작성자 자신의 작업이고, 조건마다 2~3회만 돌렸습니다.
  - 채점자는 Opus 5.5 하나입니다([`grade.mjs:22`](https://github.com/rootstudioyaml/sprag/blob/593c36d/scripts/evals/grade.mjs#L22)). reference 모드에서는 Opus 기준선 보고서가 정답지가 됩니다.
  - 비교 대상은 빈 상태에서 새로 돌린 Opus입니다. 사용자가 실제로 고르는 대안, 즉 캐시가 쌓인 메인 세션에서 직접 처리하는 경우가 아닙니다.
- **README:** A/B 표의 원자료라고 적은 `video/out/measure2.json`([`README.md:247`](https://github.com/rootstudioyaml/sprag/blob/593c36d/README.md#L247))은 git 이력 전체에 없습니다. 첫 화면의 "$6.68 → $1.83"을 만든 스크립트와 입력도 저장소에 없습니다.

### 1.7 확인했지만 문제가 없던 것과 새로 생긴 것

- **문제없음:** 무료 CLI의 외부 요청(npm, GitHub API, 프리셋 버전 조회)에는 IP 외에 식별자가 없습니다.
- **문제없음:** 프리셋 서명은 ES256이고, 공개키가 고정돼 있으며, 구버전으로 되돌리는 것을 거부합니다.
- **문제없음:** 훅을 지울 때 그룹이 아니라 훅 단위로 지워, 사용자의 다른 훅을 건드리지 않습니다.
- **새로 생김(v3.109.0):** 팀에 가입한 컴퓨터는 삼킨 오류를 진단 정보로 30분마다 올립니다. 경로·호스트·비밀값은 가리고, `SPRAG_NO_DIAG=1`로 끌 수 있습니다.

## 2. 실측 1: 긴 Opus 세션에서 직접 처리와 Haiku 위임

**방법**
- Opus 5.5 세션 하나(컨텍스트 약 26~28만 토큰, 1시간 캐시)에서 과제 두 개를 처리했습니다.
- **직접 처리:** 세션을 복제한 포크가 맡았습니다. 모델, effort, 컨텍스트가 같습니다. 포크는 5분 캐시로 썼으므로, 메인 세션의 1시간 캐시 요금으로 다시 계산했습니다.
- **위임:** Haiku 5.5 하위 에이전트에 넘겼습니다. 메인 쪽 비용(호출 두 번, 지시문, 보고서)은 실측 토큰으로 계산했습니다.
- 대상 코드는 npm 11.19의 `lib`(약 1.7만 줄)입니다.

| 과제 | Opus 직접 | Haiku 위임 | 직후 절감 | 이후 메인 호출 30번까지 포함 |
|---|---|---|---|---|
| `lib/commands`의 a~e 파일 20개를 읽고 한 줄씩 요약 | $0.530 (호출 2번) | $0.201 | 62% | $0.606 (73%) |
| `lib` 전체의 `log.warn(` 호출 위치 찾기 | $0.231 (호출 3번) | $0.158 | 32% | $0.093 (35%) |

- **왜 위임이 쌌나:** 파일 읽기는 직접 하면 내용 4.9만 토큰이 메인에 쌓입니다. 이후 호출마다 $0.009씩 더 듭니다.
- **작은 조회의 절감:** 대부분 Opus가 호출을 한 번 더 써서 생겼습니다. 두 번에 끝냈다면 절감은 약 $0.03이었을 것입니다.
- **정확도**
  - 파일 요약은 둘 다 20개를 맞혔습니다.
  - 조회는 둘 다 56건을 찾았습니다. Haiku는 마지막 합계를 "66"으로 잘못 적었습니다.
  - 첫 Haiku 실행은 목록 도구 없이 파일 이름을 추측해 2개를 빠뜨렸습니다. 빠뜨린 사실은 스스로 밝혔습니다.
- **어느 하위 모델이냐가 중요합니다.** 같은 토큰을 다른 모델 가격으로 다시 계산했습니다(이후 호출 효과 제외).

| 하위 모델 | 파일 읽기 | 작은 조회 |
|---|---|---|
| Haiku 5.5 | 62% | 32% |
| Haiku 4.5 | 47% | 12% |
| Sonnet 5.5 | 25% | −9% |

Opus 5.5와 Sonnet 5.5는 캐시 읽기 요금이 백만 토큰당 $0.2로 같습니다. 그래서 Sonnet에 넘기면 입력·출력 가격이 절반이 되는 데서만 이득이 납니다.

## 3. 실측 2: sprag 3.108.0과 기본 Claude Code

**방법**
- HOME을 분리한 격리 환경 두 곳을 만들었습니다. 한쪽은 아무것도 깔지 않았고, 다른 쪽에는 npm 최신이던 sprag-cli 3.108.0을 설치했습니다.
- 두 환경에서 같은 7턴 대화를 Opus 5.5(기본 effort)로 돌렸습니다. 대상 코드는 npm `lib` 사본입니다.
- 실제 사용자 설정(`~/.claude`)은 건드리지 않았습니다.

**설치가 한 일**
- 훅 11개, 플러그인 3개(`CLAUDE_CODE_PLUGIN_DIRS`), 매 세션 불러오는 룰 파일 약 19KB를 등록했습니다.
- 한국어 로케일이라 한국어 문체 지침과 쓰기 검사(차단 모드)도 자동으로 켰습니다.
- 대화 첫 호출의 컨텍스트가 19,140토큰에서 36,708토큰이 됐습니다.

**훅이 붙인 지시**
- 세 과제를 모두 Sonnet(effort high)으로 넘기라고 했습니다.
- "파일을 읽고 정리해줘"는 "명령 실행 (빌드·테스트·git)"으로 분류했습니다.
- node·npm 버전 확인처럼 명령 두 줄이면 끝나는 일도 넘기라고 했습니다.
- 세 경우 모두 "사용자가 이미 승인한 룰"이라고 적었습니다.

- **왜 sprag 쪽이 쌌나:** 마지막 호출의 메인 컨텍스트가 기본 179,340토큰, sprag 77,692토큰이었습니다. 읽은 파일 내용이 메인 밖에 머문 덕분입니다. 매 호출 붙는 1.76만 토큰보다 이 차이가 컸습니다.
- **정확도:** 같았습니다. 파일 요약 20개, `log.warn` 56건과 주석 2건, 버전, 뒤이은 질문 모두 일치했습니다.

- **걸린 시간:** 기본 175초, sprag 181초였습니다.
