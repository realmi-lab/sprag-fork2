# long-reader

**Claude Code의 긴 읽기를 Haiku에 넘기는 서브에이전트 하나입니다. 파일 수십 개 읽기, 저장소 전체 찾기, 긴 로그 훑기는 Haiku가 하고, Opus에는 요약만 돌아옵니다. 에이전트 파일 한 장만 깔면 Opus가 알아서 넘깁니다.**

**long-reader는 읽을 양은 많고 필요한 건 요약뿐인 일을 싼 모델에 맡깁니다.** Opus가 파일을 직접 읽으면 읽은 내용이 대화에 그대로 쌓입니다. Claude Code는 호출할 때마다 대화 전체를 다시 읽으므로, 한 번 쌓인 내용은 세션이 끝날 때까지 비용을 냅니다. long-reader를 깔아 두면 Opus가 그런 일을 Haiku 하위 에이전트에 넘깁니다. 대화에는 Haiku가 돌려준 짧은 보고만 남습니다.

설치하는 것은 에이전트 정의 파일 한 장(`agents/long-reader.md`)뿐입니다. 훅, 상태줄, 상시 실행되는 프로그램, 외부 전송이 없습니다. 에이전트 설명에 언제 넘기고 언제 직접 하는지가 적혀 있어서, 요청에 에이전트 이름을 적지 않아도 Opus가 고릅니다.

에이전트는 읽기만 합니다. 쓰기 도구가 없고, 대상 목록을 명령으로 먼저 확정한 뒤 읽습니다. 보고는 범위(N개 중 N개), 결과(`파일:줄`), 못 본 것 순서로 돌아오므로, Opus는 빠진 곳이 있는지 바로 알 수 있습니다.

```bash
git clone https://github.com/realmi-lab/sprag-fork2 && cd sprag-fork2 && ./install.sh
```

스크립트 없이 쓰려면 `agents/long-reader.md`를 `~/.claude/agents/`에 복사하면 됩니다. Windows도 같습니다.

## 설치하면 달라지는 것

1. `./install.sh`를 실행합니다. 에이전트 파일이 `~/.claude/agents/`에 들어가고, 모든 프로젝트에서 쓸 수 있습니다. 같은 이름의 파일이 있으면 `.bak`으로 남기고 바꿉니다.
2. Claude Code 세션을 새로 열고 평소처럼 일합니다.
3. "이 폴더 파일들 읽고 정리해줘", "이 함수 호출하는 곳 다 찾아줘" 같은 요청을 하면 Opus가 long-reader를 부릅니다. 보고는 이런 형태로 돌아옵니다.

```
범위: lib/commands의 a~e 파일 20개 중 20개 읽음
결과:
- access.js:1  패키지 접근 권한 조회·변경
- adduser.js:1  레지스트리 계정 추가
- ...
못 본 것: 없음
```

`./uninstall.sh`는 설치한 에이전트 파일과 CLAUDE.md 지침을 지웁니다.

## 동작 방식

```
요청 ─▶ Opus (메인 대화)
          │
          ├─ 명령 한두 번이면 끝나는 조회, 설계·진단·리뷰, 파일 수정 ─▶ Opus가 직접
          │
          └─ 파일 여러 개 읽기, 저장소 전체 찾기, 긴 로그 훑기
                 │
                 ▼
            long-reader (Haiku, 읽기 전용, 별도 컨텍스트)
                 │  읽은 원문은 여기서 끝납니다
                 ▼
            요약만 Opus에게 (범위 · 결과 · 못 본 것)
```

아끼는 원리는 두 가지입니다.

- **읽기 자체가 싸집니다.** 같은 양을 읽어도 Haiku 5.5의 입력 단가는 Opus 5.5의 40분의 1입니다.
- **이후 대화가 가벼워집니다.** 원문 대신 짧은 요약만 메인 대화에 남으므로, 다음 호출부터 다시 읽을 양이 줄어듭니다. 세션이 길수록 이 효과가 커집니다.

대신 하위 에이전트가 따로 시작하는 만큼 조금 느려집니다. 짧은 일은 이 시작 비용이 아끼는 양보다 커서, 에이전트 설명에 "작은 조회는 직접 하라"고 적어 두었습니다.

| 긴 세션(컨텍스트 약 27만), 파일 20개 읽기 | **62~77% 절감** | `▰▰▰▰▱▱▱▱▱▱▱▱` | 이후 대화 횟수에 따라 |
| 긴 세션, 작은 grep 조회 | 32~35% 절감 | `▰▰▰▰▰▰▰▰▱▱▱▱` | 보통은 본전에 가까움 |
| 정확도 | 모든 설정에서 20개 중 20개 정리 | | 직접 대조 |

- **이름을 적지 않아도 넘깁니다.** 새 세션 두 경우 모두 요청에 long-reader를 적지 않았는데 Opus가 알아서 넘겼습니다.
- **작은 조회는 넘기지 않습니다.** 버전 확인처럼 명령 한 번이면 끝나는 일은 Opus가 직접 했습니다.
- **수치의 한계가 있습니다.** 조건마다 한 번씩만 잰 값이고, Claude Code가 계산한 정가 환산입니다. 구독 요금제에서는 돈이 아니라 사용 한도가 덜 줄어듭니다. 대상은 npm `lib` 사본입니다.

### Haiku냐 Sonnet이냐

긴 세션에서 잰 같은 작업을 하위 모델 가격만 바꿔 다시 계산했습니다(이후 대화 효과 제외).

| 하위 모델 | 파일 20개 읽기 | 작은 조회 |
|---|---|---|
| **Haiku 5.5** (기본) | 62% 절감 | 32% 절감 |
| Haiku 4.5 | 47% 절감 | 12% 절감 |
| Sonnet 5.5 | 25% 절감 | 9% 손해 |

Sonnet 5.5는 캐시를 다시 읽는 요금이 Opus 5.5와 같아서 덜 아낍니다. Haiku가 자주 빠뜨리는 일이 있을 때만 `--model sonnet`을 쓰십시오.

## 맡기면 좋은 일과 직접 하는 게 나은 일

| 맡기면 좋은 일 | 직접 하는 게 나은 일 |
|---|---|
| 파일 여러 개를 읽고 요약 | 명령 한두 번으로 끝나는 조회 (버전 확인 등) |
| 저장소 전체에서 호출 위치·문자열 찾기 | 설계, 원인 진단, 코드 리뷰처럼 판단이 결론인 일 |
| 긴 로그·테스트 출력에서 실패만 추리기 | 파일 수정 |

## 명령

| 명령 | 하는 일 |
|---|---|
| `./install.sh` | 모든 프로젝트에 설치 (`~/.claude/agents/long-reader.md`) |
| `./install.sh --project DIR` | 그 프로젝트에만 설치 (`DIR/.claude/agents/`) |
| `./install.sh --model sonnet` | Haiku 대신 Sonnet 사용 |
| `./install.sh --with-claude-md` | CLAUDE.md에 지침도 추가 |
| `./uninstall.sh [--project DIR]` | 설치한 에이전트와 지침을 지움 |

새로 여는 Claude Code 세션부터 적용됩니다.

## 한계

- 쓰기 도구는 없지만 Bash가 있으므로, "읽기 명령만 쓴다"는 에이전트 지침으로만 지켜집니다. 사용자 설정이 Bash를 전부 허용한다면 이 점을 알고 쓰십시오.
- 판단이 필요한 일은 맡기지 않습니다. Haiku의 요약을 그대로 결론으로 쓰지 말고, 판단은 Opus가 합니다.
- 긴 읽기를 넘기는 일 하나만 합니다. 상태줄, 문서 변환, 팀 기능은 없습니다.

## sprag에서 착안

이 프로젝트는 [sprag](https://github.com/rootstudioyaml/sprag)에서 착안했습니다. "일을 맞는 모델의 하위 에이전트에 넘긴다"는 sprag의 아이디어 가운데 긴 읽기를 Haiku에 넘기는 부분을 에이전트 파일 하나로 옮긴 것입니다. 이 저장소도 sprag 포크로 시작했습니다.

sprag는 이보다 훨씬 많은 일을 합니다. 세션 기록에서 위임 규칙을 찾아 주고, 캐시·컨텍스트·한도를 상태줄에 보여 주며, 문서(pptx·xlsx·pdf·docx)를 Markdown으로 바꾸고, 반복 실수를 룰로 남기고, 팀 대시보드와 Codex도 지원합니다. 이런 기능까지 필요하면 sprag를 쓰십시오.

sprag 코드를 바탕으로 손본 버전은 [`review-fixes-2026-11` 브랜치](https://github.com/realmi-lab/sprag-fork2/tree/review-fixes-2026-11)에 있습니다.
